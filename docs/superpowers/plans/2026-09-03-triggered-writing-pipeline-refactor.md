# 触发式文案生成链路实施计划

## 1. 先建立失败测试

- 新增调用链契约测试：唯一权威、临时内容状态、三入口同链、停止条件、Humanizer 后复检。
- 新增旧规则清理测试：固定数量、随机轮换、隔三跳一、固定情绪收尾、复制表格、可见交接单。
- 运行测试并确认在旧实现上失败。

## 2. 重构核心编排

- 新增共享触发注册表与机器可读清单。
- 修改 `AGENTS.md`：将五大模块改为条件式技法，更新执行顺序与结构去重。
- 修改 `wenan-skill/SKILL.md`：取消可见交接单，建立同任务临时内容状态，统一三种入口和停止门。

## 3. 清理共享规则

- 修改质量门、表达技法、钩子、植入与反例规则。
- 删除会制造报告腔、假口语、假案例或固定模板的强制处方。
- 修改 Humanizer 的事实入口、宏观重组权限和触发条件。

## 4. 精简专项 Skill

- 删除各专项 Skill 复制的公共话题权重表。
- 用一行引用接入共享触发注册表。
- 把固定 Default Structure 改成按证据关系选择的候选结构。
- 数字人口播分镜保持“只拆已确认稿”，不参与重新选结构。

## 5. 更新文档与状态

- 更新 README 的现行使用方式。
- 将旧交接文档标为历史存档并移出必读链。
- 建立最小结构状态账本的空架构；只在用户确认或发布后记录，不在生成时暗写。

## 6. 验证

- 运行全部静态测试。
- 搜索全部旧规则和重复公共表格。
- 用若干不同证明义务的真实任务做独立行为检查。
- 复核事实优先级、植入资格和日更多样性不会互相覆盖。
