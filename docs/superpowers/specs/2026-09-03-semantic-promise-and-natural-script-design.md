# 语义承诺锁与自然口播去模板设计

日期：2026-09-03

## 目标

在不削弱事实、证据和单一内容承诺的前提下，删除会把文案压成固定问答、三段推进、功能型结尾和重复句框的硬模板；同时解决“同一项目、同一产品，但正文没有回答标题问题”的承诺维度漂移。

本设计固定审核流程，不固定可见正文结构。

## 已确认删除

1. 删除轻钢、移动卫浴和消防专项 Skill 中可直接仿写的完整句框、`Prefer` 示例和“短句优先”要求。
2. 删除生成前的强制问题化、完整问题示例、最多三个推进动词、逐段动作标记、预设结尾任务和固定功能型收尾。
3. 公司或产品植入从所有稿件的默认步骤改为条件触发：用户明确要求、产品本身是主题，或新闻流程已选定产品时才进入详细资格检查。
4. 删除“每一段必须提供某类新信息”及共享文件中的等效逐段规定。
5. 删除“下期预告不能推翻本期的条件式结论”及等效专项规定；不保留预告专属规则，统一由事实一致性和语义承诺检查处理。
6. 删除各专项 pattern 中重复的公共正文路线和 `End with...` 结尾菜单；专项参考只保留领域事实、证据边界和风险差异。

## 必须保留的硬边界

1. 所有实质性事实可追溯，结论强度不超过证据。
2. 一条稿件只兑现一个内容承诺，不混入第二个可独立成稿的主题。
3. 标题、开头和正文必须兑现同一个承诺；产品或公司内容只有与该承诺直接相关且有证据时才能出现。
4. Humanizer 可以重排句子和段落，但不能改变事实命题、限定条件、责任关系和因果强度。
5. 最终只交付一份通过检查的口播稿及必要资料出处。

“一条稿件只讲一个核心问题”统一改成“一条稿件只兑现一个内容承诺”，避免把所有正文诱导成反问自答。

## 语义承诺锁

起稿前在同任务临时状态中只锁定：

- 对象与场景；
- 标题要求判断的动作或变量；
- 本稿必须给出的答案；
- 答案的证据强度与适用边界；
- 与本题相邻但不能替代本题的问题。

锁定的是语义靶心，不是正文顺序。它不得规定段数、问句、连接词、钩子句式或结尾形式。

例如《NEOM 数据中心开工，打包箱该不该马上定？》的判断变量是“采购时机”。产品是否灵活、怎样配置、模块化有什么价值，除非能够用证据说明它们如何改变采购时机，否则不能替代标题答案。

## 承诺可回答门

生成前，“可证结论”必须是标题承诺的直接答案，不能独立选择一个更容易证明的相邻结论。

资料不足以回答标题时，只允许：

- 补充证据；
- 将标题改为证据能够兑现的承诺；
- 缩短为资料实际支持的有限答案；
- 停止成稿并说明缺口。

不得用同项目、同产品或同领域的相邻知识补足参考篇幅。

## 正文相关性检查

不再按段落规定功能。只对实质性事实、参数、案例和产品主张判断：它是否直接回答标题承诺、提供回答所需的证据，或解释证据为什么会改变答案。

三者都不成立时移出本稿。自然过渡、口播停顿和必要解释不要求提供新的专业知识。

仅共享项目名、产品名、行业或关键词，不构成相关性。即使始终讲同一个项目和产品，只要没有回答标题要求判断的问题，仍然属于离题。

## 成稿后的反向答案检查

Humanizer、篇幅调整和植入完成后，先不看标题，只根据最终正文提取一句“这篇实际回答了什么”。再与语义承诺锁比较：

- 对象与场景；
- 判断动作或变量；
- 实际答案；
- 结论强度和边界。

判断变量不同即失败。例如标题问“什么时候订”，正文实际回答“为什么适合模块化”，不能靠末尾补一句采购建议通过。

这道检查放在最终事实复检之前；任何改写后都必须重新执行。

## 钩子、结尾、篇幅与植入

- 正文证明内容完成后再设计首句，钩子只负责准确引出已存在的承诺。
- 最后一个必要事实、动作或边界已经完成承诺时直接结束，不单独生成收尾；只有用户明确需要 CTA 或内容确有未完成任务时才补充。
- 用户明确篇幅或时长时前置执行；未指定时，三份账号语料的篇幅只在成稿后检查完整度，不作为起稿配额。
- 植入是条件分支，不是每稿槽位。公司名称、能力和产品卖点分别经过相关性与证据检查。

## 自然口播与表层重复

Humanizer 对整稿检查 `先 A 再 B`、`别只 A 要看 B`、`不是 A 而是 B`、`A 能不能 B`、`所以＋前文复述` 等句法骨架。单个词不构成禁用；同一骨架反复承担相同功能时，必须改变信息组织、主语或顺序，不能只换同义词。

段落按连续语义和真实口播呼吸分合，不按“一段一个动作”切分。最后一句只复述前文且删除后不损失答案、边界或必要 CTA 时，直接删除。

## 多样性

内容关系和表层句法指纹只在成稿后提取，用于识别近期重复，不在起稿前拼装结构。只有存在同样准确、同样有证据的其他组织方式时才调整；事实只允许一种顺序时，真实性优先。

## 调用链

`事实与边界核验 → 锁定语义承诺 → 承诺可回答检查 → 自然起稿 → 正文完成后处理钩子 → 条件式植入 → Humanizer 整稿口播审查 → 后置篇幅检查 → 反向答案检查 → 事实复检 → 提取结构与句法指纹 → 输出`

## 验收标准

1. 项目中不再存在生效的 `Use short spoken sentences`、正文 `Prefer` 成品句、起稿前预设结尾或逐段动作要求。
2. 生成流程包含承诺可回答门和成稿后的反向答案检查。
3. 图片中的反例必须失败：标题问采购时机，正文改答产品适配或模块化价值。
4. 同一正文换成与其实际答案一致的标题时可以通过，证明检查的不是关键词。
5. 自然过渡和场景铺垫不因“没有新知识”被误删。
6. 无证据支持原标题时，系统缩短、改题、补资料或停止，不用相邻知识凑篇幅。
7. 不要求反问自答、固定段数、固定结尾、固定 CTA 或固定句长。
8. Humanizer 修改前后事实命题、条件、责任和结论强度保持一致。
9. 所有规则测试通过，并增加上述语义行为回归场景。
