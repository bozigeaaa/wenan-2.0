# 触发式文案生成链路设计

日期：2026-09-03

## 目标

在当前项目、同一任务内完成标题选择和文案生产，不再要求用户生成、复制或提交“标题交接单”。系统用临时内容状态锁定已经确认的事实与方向，再按证据关系选择结构，避免五大技法只写在文件里却没有实际调用，也避免把所有文案压成同一模板。

## 核心设计

1. `wenan-skill` 是完整文案的唯一编排入口。
2. 标题确认后，系统在当前任务内建立临时内容状态；直接要求完整文案时，也先静默建立同一状态。
3. 临时状态只锁定“写什么以及凭什么”：受众、内容承诺、可证结论、主张与来源、适用边界、产品或公司角色、待解决项。
4. 临时状态不锁定最终钩子、段落顺序、连接词、品牌出现位置、结尾句式或 Humanizer 的改写方式。
5. 正文结构由“结论需要怎样被证明”触发。结构候选包括条件分支、同口径比较、因果追踪、时间或动作链、责任交接、证据审查、单机制拆解、真实案例复盘、明确假设推演和可核算账。
6. 钩子、过渡、口语化、植入和收尾是条件式能力，不再要求每稿机械凑齐句式、数量或轮换编号。
7. 生成后重新检查事实、标题兑现、报告腔和近期结构相似度。去重只在同样有证据支持的结构之间择优，不能为了多样性制造事实。

## 触发顺序

`任务路由 → 事实与来源 → 临时内容状态 → 证明义务 → 主信息关系 → 推进动作 → 植入资格与角色 → 结尾任务 → 钩子与表达 → 口语化复检 → 事实复检 → 结构去重`

若有待核事实、新闻未核验、产品未选定或公司关系不成立，流程停在相应门，不输出伪完成稿。

## 多样性

用六维结构签名比较近期已确认或已发布文案：入口任务、主信息关系、推进动作、证据形态、公司角色、结尾任务。完全相同则重选有证据支持的候选；四项以上相同则警告并检查。没有历史状态时不得声称完成跨稿去重；事实只允许一种结构时允许重复并说明原因。

## 权威边界

- `AGENTS.md` 只保留公共原则和总流程。
- 共享触发、结构和状态规则集中在一个 reference 与机器清单中。
- 专项 Skill 只保留领域资料、风险和差异，不复制公共技法表。
- Humanizer 只在事实状态明确后调整表达；直接收到用户旧稿时，未核实主张不得自动视为事实。
- 历史交接文档退出有效规则链，仅作存档说明。

## 验收

1. 三种入口——标题对话、用户给明确标题、直接要求完整文案——都建立相同的临时内容状态。
2. 用户不再看到或搬运标题交接单。
3. 每个生成阶段能从唯一权威文件找到触发条件、输入、通过条件和停止条件。
4. 旧的固定三逻辑、随机轮换、隔三跳一、固定句长、短爆句、强制情绪收尾、固定正文骨架均不再生效。
5. 专项 Skill 不再复制公共话题权重表或五大技法全文。
6. 静态测试验证接线和冲突消除；独立行为测试验证真实生成不会退回报告式列举。
