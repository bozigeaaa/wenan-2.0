# 工程热点新闻与产品组合选择流程设计

日期：2026-09-02

## 背景

当前六个文案大类中，前五项属于产品或业务场景，“工程热点与新闻”属于选题来源模式。用户选择“工程热点与新闻”后，系统曾错误地要求用户再次从其余五类中选择业务场景。

该错误来自阶段边界不够明确：规则要求在生成标题方向前把具体新闻映射到业务场景，但这项映射应在新闻检索和真实性复核之后由系统完成，不能提前成为第二次大类选择。

## 目标

- 用户选择“工程热点与新闻”后直接进入新闻检索，不再二次选择大类。
- 系统先检索、核验和去重，再判断新闻对应的业务场景与产品适配。
- 展示本轮检索中全部合格的独立新闻事件，不设置固定的 1—3 条上限。
- 每条合格新闻列出所有真正适配的产品及各自独立的结合理由。
- 用户一次选择“新闻编号＋产品编号”，随后才进入标题方向生成。

## 非目标

- 不展示全部原始搜索结果。
- 不为达到某个数量而保留旧闻、重复报道或产品关联不足的新闻。
- 不自动替用户选择新闻或产品。
- 不因产品适配而暗示公司参与、供货或服务该新闻项目。
- 不改变现有新闻来源优先级、事实核验标准和产品事实边界。

## 术语

- **搜索结果**：搜索工具、站内搜索或新闻渠道返回的原始线索，尚未完成核验。
- **独立新闻事件**：按事件主体、地点、日期和项目动作去重后的新闻对象；同一事件的多家转载合并处理。
- **合格新闻**：完成真实性与时效复核，并通过项目阶段、业务场景和产品适配硬门的独立新闻事件。
- **可结合产品**：能够形成“已核实新闻事实 → 项目动作或现场条件 → 产品价值”完整链条的产品。统一使用“可结合产品”，不使用容易暗示确定需求的“推荐产品”。

## 目标流程

```text
用户选择“工程热点与新闻”
→ 按既有 P0—P4 规则检索新闻
→ 打开原文并核验真实性、日期、主体、地点和当前状态
→ 按独立事件去重
→ 判断项目阶段和可转化的业务场景
→ 执行产品适配硬门
→ 展示本轮全部合格新闻及其可结合产品
→ 用户选择“新闻编号＋产品编号”
→ 锁定新闻、产品和结合理由
→ 生成标题方向候选
```

“明确业务场景”是系统在新闻核验后的内部判断，不是用户在检索前需要完成的第二次大类选择。

## 新闻展示规则

每条合格新闻使用一个稳定的当轮编号，例如 `A`、`B`、`C`。每个可结合产品使用组合编号，例如 `A1`、`A2`、`B1`。

每张新闻核验卡至少包含：

- 新闻编号；
- 发布渠道、原链接、原标题、中文直译和发布时间；
- 内容摘要；
- 已确认事实；
- 项目阶段；
- 可转化的业务场景；
- 不能从新闻直接推出的内容；
- 复核来源；
- 一个或多个可结合产品；
- 每个产品独立的结合理由；
- 核验结论。

产品结合理由必须使用以下逻辑：

```text
新闻事实
→ 具体项目动作、施工阶段、现场条件或交付需求
→ 产品可以帮助回答的同一个项目问题
```

不得把“项目规模大”“同属建筑行业”“发生在沙特”或“新闻出现相近产品词”单独作为产品适配理由。

## 数量与去重规则

- 不设置固定展示上限；展示本轮实际检索范围内的全部合格独立事件。
- 同一事件的不同媒体报道合并为一张新闻核验卡，多个来源进入复核来源字段。
- 同一事件没有实质新进展时，不因标题或媒体不同重复展示。
- 如果合格事件过多导致单次输出超出界面或上下文承载能力，可以分批展示；首批必须说明合格事件总数、本批数量和剩余数量，并提供继续查看入口，不得静默省略。
- 事件排序只影响展示顺序，不影响是否展示。排序依次参考时效、事实可靠性、项目阶段清晰度、产品关联强度和受众决策价值。

## 用户选择规则

- 多条新闻或多种产品并存时，用户回复组合编号，例如 `B2`，同时锁定新闻与产品。
- 只有一条新闻时，用户可以回复产品名称或产品编号；系统将其解释为该新闻下的产品选择。
- 用户选择后，新闻事件、产品名称、结合理由、事实范围和新闻状态全部锁定。
- 后续标题不得切换到其他新闻、其他产品或纯新闻评论。
- 用户明确要求同时选择多个产品时，只有这些产品能够共同回答同一个营地或配套问题，才允许组合；否则建议拆成多条内容。

## 无合格新闻时

如果本轮没有任何新闻同时通过真实性复核和产品适配：

- 按既有新闻搜集反馈格式列出实际访问渠道、访问方式和未采用原因；
- 不展示无产品关联的新闻凑数；
- 让用户选择进入常青议题，或明确切换产品方向后重新检索。

## 事实与营销边界

- “可结合产品”只证明该新闻能够转化为相应业务判断，不证明新闻项目存在确定采购需求。
- 不推断项目采购数量、现场人数、库存、交期、价格、供应商或公司参与关系。
- 公司名称进入后续文案时，继续遵守新闻核验卡例外和公司软植入规则。
- 标题和正文必须保留用户选定的新闻、产品及结合理由，并只讲一个核心问题。

## 验收场景

1. 用户选择第 6 类后，系统直接检索新闻，不再展示其余五类要求二次选择。
2. 本轮存在三条合格独立事件时，三条全部展示，每条列出各自真正适配的产品。
3. 三家媒体报道同一项目动作时，只展示一张事件卡，三家来源用于复核。
4. 新闻真实但没有产品适配链时，不进入核验卡。
5. 合格事件超过单次输出承载能力时，系统明确报告总数和剩余数，再分批展示。
6. 用户回复 `B2` 后，后续标题方向保持新闻 B、产品 2 和该产品结合理由。
7. 用户尚未选择组合编号时，不生成标题、正文或公司营销内容。
8. 没有合格新闻时，输出真实的新闻搜集反馈，不强行关联产品。

## 成功标准

- 不再出现选择“工程热点与新闻”后要求用户二次选择大类的流程。
- 所有展示新闻均可追溯、已去重并通过产品适配硬门。
- 本轮合格事件不会因固定数量上限被静默隐藏。
- 用户只需一次选择即可同时锁定新闻和产品。
- 后续标题与文案能够稳定沿用同一新闻事实、产品和业务问题。
