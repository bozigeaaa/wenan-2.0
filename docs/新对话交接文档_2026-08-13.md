## 1. 项目目标与受众

本项目为东方骆驼/深圳钧瀚的中文 B2B 短视频文案工作台，主要发布在国内抖音，也会分发至其他平台。

有两个账号：

- **营销账号**：目标是获得有效咨询和留资，但不靠夸张承诺、虚构案例或强塞广告。
- **科普账号**：目标是自然可信、易懂、观众不需要费力理解；默认不强带品牌。

核心受众是已在沙特、正在投资沙特或准备进入沙特的中文项目决策者，包括项目经理、采购、营地管理者、EPC/总包等。内容可涉及临建、营地、预制建筑、轻钢、移动卫浴、物流交付、审批合规及项目管理。

团队日常唯一入口为 `$wenan-skill`（界面显示为“文案 Skill”）。它根据任务自动路由至专项能力；同事不必记忆各专项 Skill 名称。

## 2. 已确认的内容原则

1. 所有内容优先级固定为：**真实性和可追溯性 → B2B 决策价值 → 单点逻辑和口播清晰度 → 标题与传播性**。
2. 一条视频只回答一个核心问题；标题、开头、正文、公司落点与结尾必须回答同一问题。
3. 不把“中国发货”作为默认叙事中心。仅在航运、港口、进口、跨境采购、到场交付、仓储、配送、安装等直接相关时，才讨论本地制造和交付责任链。
4. 本地化差异化的正确表达是引导客户核对生产主体、常规品调配、配件接口、配送安装、验收与后续维护责任；不得把竞品称为“二道贩子”，不得断言小工厂没有库存、配件或安装能力。
5. 新闻与建设项目同属行业，不等于该项目必然需要东方骆驼的材料或产品。只有能自然形成“现场人员、临时空间、施工营地、办公、住宿、卫浴、围挡、仓储、配送安装或运营切换”的复核动作时，才可写成临建相关内容。
6. 战争、灾害、制裁、重建等高敏感事件不能作为常规销售钩子；如需使用，必须单独核验事实、保留不确定性并人工审稿。

## 4. Humanizer Plus 的实际定位

Humanizer Plus 只处理表达层：去明显 AI 腔、宣传册腔和模板化口播，改善句长、停顿、转折和自然度。

它**不负责**：事实核验、新闻来源、法规判断、参数选择、项目结论、标题选题、品牌露出策略或留资策略；也不得新增数字、案例、客户反馈、效果承诺或因果关系。

项目内已接入的规则是：

- `.agents/skills/references/b2b-content-quality-gate.md`：B2B 选题、逻辑、标题与发布风险质量门；
- `.agents/skills/references/b2b-humanizer-expression-gate.md`：Humanizer 表达审校层；
- `.agents/skills/script-oralization-rewriter/`：用户明确要求“更口语、像真人、去 AI 味”时的强化改写入口。

此前一次临时 `humanizer-zh-plus` 输出目录在后续工作目录切换时未找到；新对话不要声称存在可单独调用的该临时目录。应以项目内上述共享表达规则为准。

## 5. 新闻、来源与热点台账

热点 Skill：`.agents/skills/global-hotspot-industry-impact-script/`。其原则如下：

1. `search` 只负责发现候选；必须打开或抓取原文，核对日期、主体、地点、状态和原始链接后才可写。
2. 来源分级：
   - A 级：政府、监管、港口、项目业主、招标平台、上市公司、承包商、船公司、保险机构等一手公告；
   - B 级：Reuters、AP、AFP、Bloomberg 等交叉核验；
   - C 级：工程/航运/物流/能源媒体、项目数据库、搜索结果，仅作线索，不单独证明关键事实。
3. 时效规则：0–7 天可作为突发热点；8–30 天只有仍在持续或有实质新进展时可用；超过 30 天只能作背景或常青素材，不能包装成近期热点。
4. 未使用付费 Firecrawl API，也没有创建监控。当前模式是每次创作时人工检索、打开原文、核验、再更新台账；不得宣称每日自动更新。

热点台账是唯一使用记录源：`content-state/hotspot-ledger.json`。写热点稿前读取，写完后更新；低并发下由一人更新。多人同时写时 JSON 会有覆盖风险，应改用 SQLite 或共享数据库，不能只靠更多文字规则。

## 6. 建设新闻选题—成稿—复盘闭环（本次新加）

### 6.1 候选关键词与来源

- 现场配套：施工营地、临时设施、现场办公、工人住宿、卫生设施、围挡、仓储、项目配套、劳务营地；
- 重点主体/地区：Saudi Arabia、Riyadh、Jeddah、NEOM、ROSHN、Diriyah、Qiddiya、RCU、MODON、RCJY、Mawani、Etimad。

常用官方/一手入口包括 Etimad、SPA、MoTLS、SAR、MODON、Mawani、NEOM、ROSHN、Diriyah、Qiddiya、Tadawul，以及具体项目业主或承包商公告。它们是优先入口，不是唯一来源；具体新闻仍以原文核验为准。

### 6.2 选题门槛

每条建设新闻要先标：

- `project_stage`：招标/预资格、授标/签约、开工、施工推进、扩建、收尾/调试、投运、政策/物流信号或不适用；
- 临建关联判断：能否引出与现场配套直接相关的复核动作。

融资、概念规划、设计竞赛、主体结构技术、无现场配套关系的设备新闻，只保留为行业背景；不要硬转为临建材料或产品推广。

同一项目默认一条新闻解读。只有出现新的可核验阶段变化时，才可切换核心问题：启动阶段讲准备、施工推进讲空间/人员变化、收尾调试讲临建撤留与功能切换。不得只换标题重复。

### 6.3 双账号与品牌证据桥

- **科普账号**：默认带出相关公司和产品内容，公司和产品必须参与回答同一个核心问题；表达要清楚、易懂，不能只提名称或突然插入广告。只有用户明确要求不写公司和产品时才省略。
- **营销账号**：公司和产品都要进入同一个核心问题；只可使用与当前问题同一责任链上的、已在公司台账或用户确认范围内的能力；结尾提出主题对应的低压留资动作，例如项目阶段、用途、地点、预计人数或时间窗口。
- 同一新闻用在两个账号，必须换标题、核心问题和脚本结构，不能只是科普稿末尾加广告。

品牌证据桥的位置、顺序和长度按信息关系决定，不套固定段落：可用 `客户先核对什么 → 东方骆驼可依据什么真实能力协助什么 → 具体方案按项目要求确认`，但不要求每篇都照此排列，也不罗列无关优势。

需要同步准备相匹配的工厂、产品、现场或交付资料画面；没有可用证据画面时，只能降低为可核对的能力说明，不能加强承诺。

### 6.4 发布后复盘

热点台账的 `used_angles` 新增以下建议字段：

- `account_type`：`education` / `marketing`；
- `project_stage`；
- `brand_presence`：`none` / `evidence_bridge` / `solution`；
- `cta_type`：`none` / `self_check` / `interaction` / `lead_capture`；
- `publication_review`：复盘状态、有效咨询及已获得数据；未有数据写“待复盘”。

复盘不能只看播放量。至少记录选题、受众、核心问题、是否带品牌、完播/互动质量、有效咨询、客户问题，以及下次保留/避免的角度。数据不足不下结论。

## 8. 新对话的建议启动顺序

1. 先读本文件与 `AGENTS.md`；
2. 读 `knowledge/AI资料导航索引.md`，再按任务读取相关原始资料；
3. 如果是新闻/项目选题，读热点台账、来源规则和建设新闻闭环；联网检索后必须打开原文核验；
4. 如果涉及公司能力，读公司主张台账；
5. 先内部确定账号类型、一个核心问题、是否自然关联临建、是否需要品牌证据桥；
6. 生成全稿后走 B2B 质量门；用户要求口语化/去 AI 味时，再做 Humanizer 表达层审校；
7. 输出实际用到的 `资料出处`；热点成稿后回写台账。

## 9. 常见避坑清单

- 不把搜索摘要、转载或旧新闻直接当事实；
- 不把“可能影响”写成“已经造成延期、涨价、停工、验收失败”；
- 不把一般建设新闻强行写成“需要我们的材料”；
- 不把科普突然转为广告；不在每条稿里硬提东方骆驼；
- 不用“行业内幕”“所有人都不知道”“不这样做就停工”等恐吓式标题；
- 不捏造客户案例、订单、现场画面、库存、交期、施工人数、资质、法规结论和结果数据；
- 不把法规的性能要求说成“强制必须购买某产品”；
- 不混淆进口/清关场景与本地制造/本地交付场景；
- 不为凑时长用相邻知识、假现场感或夸张后果填充；
- 不把 Humanizer Plus 当成事实/转化/选题能力；它只优化表达层；
- 不自动创建或宣称使用付费 Firecrawl 监控。
