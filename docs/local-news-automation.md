# 本地新闻日报自动化

在 Codex 打开本项目文件夹，新建一个项目对话，说“收集新闻”。入口会先做本机自检，运行首轮采集与逐条核验，并创建每日自动收集。仅想运行一次时说“只收集这一次新闻，不启用自动化”。

## 每天怎样运行

每天北京时间09:00和14:00各启动一次收集与核验，完成后在新闻任务中汇报。上午和下午分别记录完成情况，下午增量更新当天日报；同一批次重复触发且已完成则静默跳过。取消每15分钟检查。应用关闭时不执行本地采集，错过的内容合并到下一次可运行的计划批次，不承诺重新打开立即补跑。

本机已创建“每日新闻收集与核验”，附着到独立的“新闻收集自动化”任务。自动化由 Codex 管理，停止或修改时直接在 Codex 说出要求。当前项目路径、自动化 ID 和对话 ID 保存在 outputs/news/automation-local.json，仅供本机使用；其他用户下载后通过自己的 Codex 工具注册，不复制该文件里的本机 ID。

本地运行需要电脑保持开机、Codex 应用保持运行，项目目录可读写并能联网。使用者的账号、工具授权与额度由使用者自己的环境提供。系统通知是否弹出遵循本机通知设置；日报结果在对应新闻任务中保留。

## 输出

- outputs/daily-news-demo.html：最新简报，包含最近15个自然日有收录的数据，可离线打开。
- outputs/daily-news-YYYY-MM-DD.html：当日 HTML。
- outputs/news/YYYY-MM-DD.json：当日结构化数据，作为跨对话与上午/下午分批次去重依据。
- outputs/news/evidence-YYYY-MM-DD/：本轮实际访问和事实核验依据。

每条新闻均在收集时写入核验状态、核验时间、核验方法、结论与原文/复核来源。证据不足的记录保留明确缺口，默认列表仅显示已核验条目。新闻核验和产品适配分别判断。所有复制指令使用所选日期和该条新闻编号。

在 HTML 选择新闻及产品后，复制选题指令到专门写文案的项目对话。新闻任务不自动生成标题、口播稿或分镜。

## 开发与验收

新闻的发现和事实判断由 Codex 依 daily-industry-news 技能执行；scripts/daily_news.py 只负责结构校验、当前批次是否到期和 HTML 生成。使用 Python 3.10+，不需另装报表依赖。网络抓取工具按项目 Scrapling 技能准备，每轮必须至少两种工具实际检索，默认采用 Scrapling + Firecrawl；不可用时以其他实际可用工具补足。发布程序会检查双工具记录，缺少时不能标记本轮完成。

依次执行 python scripts/daily_news.py check、python scripts/daily_news.py due；采集数据写入临时 JSON 后，执行 python scripts/daily_news.py publish <临时JSON>。校验失败不会覆盖现有 HTML。字段合同见 .agents/skills/daily-industry-news/references/report-format.md。

## 筛选与文案使用记录

顶部四个统计卡片可点击筛选已核验、全部、产品相关或核验未通过的新闻。点击时清除搜索词和产品分类限制，结果数量与统计口径一致。

每条新闻右上角的“未使用”按钮可记录文案使用情况。有多个适配产品时分别勾选，按钮显示“已用 1/4”等进度；无适配产品时标记整条新闻。取消勾选即可撤销，复制选题指令不会自动标记为已使用，也不会改变事实核验状态。

当前版本的标记保存在当前浏览器的本地存储中，以原文链接识别新闻。同一 HTML 页面切换日期、刷新页面后保留；不同浏览器、不同电脑或不同 HTML 文件之间不保证同步，清除浏览器数据可能丢失记录。推荐固定打开 daily-news-demo.html，通过页内日期选择查看归档。记录不会写入新闻 JSON 或上传 GitHub，暂不提供团队共享。
