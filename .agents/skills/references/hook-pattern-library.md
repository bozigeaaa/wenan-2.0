# 钩子写法库

> 用途：为中文口播短视频选择能自然进入本题的开头。钩子由已核实事实、真实决策矛盾或用户提供的场景产生，不从句式模板反推事实。事实边界仍受 `AGENTS.md`、原始资料和证据台账约束。

## 开头先抓住听者

- 结论本身有清楚差异或决策价值时，可以直接说判断，不额外制造悬念。
- 受众确实面对选择、误判或流程断点时，可以用提问、对比或场景进入。
- 完整口播都用钩子开场，执行 `expression-craft.md` 的直接对话和问句上限；严肃内容也要说得顺口，传播张力不能高于证据强度。

任何开头都应让观众在不依赖标题的情况下尽快知道对象或场景。第一句已经清楚时直接推进；第一句只设置悬念时，最迟第二句话补足必要语境。

## 从八类钩子中选择

选择反常识、利益前置、痛点共鸣、悬念留白、数字冲击、场景代入、冲突对比或提问式中的一种。开头带“你”或“你的”，第一句进入主题；提问式紧接着给答案。不以新闻播报开场，新闻按 `expression-craft.md` 压成一句背景。下面的信息关系用于核对钩子是否有依据，不替代口语要求。

## 按事实关系选择角度

### 直接判断

适用：资料已经支持一个清楚、非基础的判断。

写法：先说判断，再说明它在哪个条件下成立。判断本身足够有用时，不补“很多人不知道”或情绪词。

### 真实问题

适用：受众确实需要在两个方案、两个时间点或两套责任之间做选择。

写法：问一个正文能够回答的问题。答案取决于条件时，把关键条件留在问题或紧接的下一句里。

### 有共同口径的对比

适用：两个对象可以用同一成本、用途、时间、性能或责任口径比较。

写法：先点出容易混淆的表面相同，再给出真正影响判断的差异。没有共同口径时不用对比。

### 已核实的流程断点

适用：前后步骤存在可证明的依赖，晚一步会改变配置、责任或成本口径。

写法：从依赖关系进入，不把一般麻烦升级成停工、处罚或确定损失。

### 已核实的具体事实

适用：数字、规则、项目状态或产品差异已从原始来源核实，且它直接回答本题。

写法：只使用证据支持的精度和强度。数字并非必要时不为“具体”硬塞数字。

### 来源明确的场景

适用：场景来自用户素材、可公开案例或已核实新闻，并且与本题直接相关。

写法：保留主体、时间、地点和适用范围。没有来源时改写为一般条件或直接判断，不虚构客户、甲方表情、项目现场、验收倒计时或结果。

## 症状检查

出现以下症状时重写开头：

- 只有“很多人、大家、众所周知、今天介绍”之类泛化主体，没有具体问题。
- 用“恐惧、内幕、权威、都在抢”等情绪替代事实。
- 把可能风险说成已发生事故、罚款、停工、涨价或客户投诉。
- 为了画面感虚构项目、客户、甲方反应、具体地点或时间。
- 提出正文不回答的问题，或用一个产品开头却在正文改讲另一件事。
- 只是把标题换几个词再念一遍，没有增加语境或推进。

这些表达不是逐词黑名单。若词语来自真实声纹且句子有具体信息，可以保留；判断对象是整句承担的功能。

## 使用流程

1. 读取临时内容状态中的语义内容承诺，确认对象与场景、判断动作或变量、必须给出的答案、证据强度与适用边界、目标受众和可用证据。
2. 判断事实之间最自然的入口关系；没有强张力也可以直接进入判断。
3. 写出开头后检查：主体和条件是否足够、调门是否匹配证据、正文是否能兑现。
4. 与近期稿件比较开头角度和句法骨架。只有存在同样准确的替代时才换角度，不为去重补造事实。
