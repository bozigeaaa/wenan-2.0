# Professional Knowledge Fact Rules

## High-Risk Facts

Verify before stating:

- Saudi policy, agency, platform, or regulation names.
- SBC, Civil Defense, Salamah, SABER/SASO, ZATCA, customs, LCGPA, IKTVA, PIF Musahama claims.
- Approval outcomes, rejection reasons, enforcement actions, fines, timelines, required documents.
- Whether a document package applies to local Saudi delivery, local manufacturing, imported goods, or cross-border procurement.
- "Must", "mandatory", "all projects", "system directly rejects", or similar absolute claims.

## Evidence Depth

- Treat a service page's broad label as a lead, not automatically as usable script detail.
- When the title promises a concrete scope, review item, or change, open the official requirement, guide, FAQ, or primary document and extract the facts that satisfy that promise.
- Do not repeat abstract labels such as "health, technical, and safety requirements" as if they were practical value. Either name verified examples relevant to the title or omit the label.
- Do not invent a fixed ratio, configuration, consequence, or common project behavior when the source only states a general requirement.
- Keep an internal sentence-to-source map. A source must support the sentence itself, not merely the broad topic.

## Scenario Boundary

Before using a fact, classify it on all relevant axes:

- Facility: residential building, residential compound, mobile cabin, or another temporary facility.
- Role: owner, tenant, project implementer, employer, operator, supplier, consultant, or authority.
- Concept: ownership/site-use evidence, applicant identity, required document, inspection item, technical condition, or approval outcome.
- Supply path: Saudi-local manufacture/delivery or imported/cross-border procurement.

Never treat adjacent concepts as interchangeable. In particular:

- "Project implementer" is a responsible-party role for a project scenario; it is not a third type of property ownership beside owned and rented.
- Property or site-use evidence is not proof that every temporary building has an independent real-estate title.
- Application documents are not automatically inspection criteria, and inspection criteria are not automatically application steps.
- A rule for permanent buildings or residential compounds does not automatically apply to mobile cabins.
- When one official page combines buildings, compounds, and mobile cabins, classify each requirement before using it. Page-level co-location is not proof that every listed document or ownership concept applies identically to every category.
- For project mobile cabins, do not introduce building ownership deeds or building lease contracts merely because they appear in a generic service requirement list. Use only category-specific facts or clearly identified project-site/use evidence that the source supports.

If the official source supports a narrower boundary, use only that boundary. If it does not resolve the boundary at all, leave the point out.

## Permitted Claim Strength

- State applicability variables only when the source identifies them; do not turn a list of possible variables into a stock disclaimer.
- Keep project-specific requirements conditional and scoped to the facility, responsible party, supply path, and approval route supported by the source.
- Mention added complexity in government, state-owned, PIF, or Aramco systems only when evidence identifies the relevant procurement or approval difference.
- Treat contracts, drawings, owner requirements, and authority guidance as distinct evidence layers. Identify which layer supports the claim instead of using them as an interchangeable closing phrase.
- Separate import/customs documents from Saudi-local project and delivery records. Name a document category only when the source supports its relevance to the current scenario.

## No Inference Filling

Do not add these merely to make a hook stronger or a script longer:

- A normal process presented as a mistake, such as implying that an application should be submitted before the required plan exists.
- Unverified rework, rejection, delay, stoppage, fines, extra payment, coordination failure, or supplier behavior.
- Unsupported claims that a permit, approval, or process has a missing step when the source only lists conditions or information.
- Vague references to unnamed later conditions after the supported conditions have already been identified.

When the verified material is too thin for the requested runtime, say the angle is too narrow or recommend a better title. Do not pad it.

## Product Boundary

只有出现以下任一条件，才调度公司或产品的详细植入资格检查：

- 用户明确要求公司或产品。
- 产品本身是主题。
- 新闻流程已选定产品。

三项均未触发时，不检查也不写入公司或产品。触发后，规则事实和产品能力按兑现同一内容承诺所需的证据关系组织，不设“先讲规则、再讲产品”等固定顺序。只使用已核实的产品能力，也不得从“具备某项能力”推导出审批必然通过。
