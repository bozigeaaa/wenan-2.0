# 独立行业新闻日报

## 入口与首次启用

用户在本项目的新对话说“收集新闻”“新闻日报”“初始化新闻收集”时使用本技能。先说明本项目默认会执行首轮收集并启用每日自动收集；用户明确只要一次时只运行当次。当前任务只负责新闻，不生成标题候选、口播稿或分镜，也不自动发消息给写稿对话。用户自行从 HTML 复制选题指令。

读取项目 AGENTS.md、references/collection-config.json 和 ../global-hotspot-industry-impact-script/references/hotspot-sourcing.md。该共享文件的渠道访问、方式切换、事实核验、日期、来源独立性和访问限制规则继续生效。本入口采用已配置的全部行业范围，不要求先选文案大类；日报收录本轮实际发现的所有相关事件，不套用写稿入口的三张卡片上限或等待选产品步骤。产品不适配的真实新闻仍收录为行业信息。

首次初始化先执行下方自检；检查当前账号已有自动化，按项目绝对路径和技能名称匹配，更新匹配项以免新对话反复创建。使用 Codex automation_update 工具注册本对话的 heartbeat，名称“每日新闻收集与核验”，每天北京时间09:00和14:00各运行一次，ACTIVE，使用默认通知设置。若用户指定了已有新闻对话，附着到该对话。不要新建每天一个对话，不修改其他项目的自动化。记录工具实际返回的 id、目标对话、项目路径和启用时间到 outputs/news/automation-local.json，此文件仅本机使用。定时任务只能由自动化工具创建，不能靠编写配置文件声称已启用。

调度提示按本技能的“每次运行”执行，并写明：北京时间09:00和14:00分别记录完成情况；仅本批次已完成才静默跳过。每个批次均收集、逐条核验、更新 HTML 后汇报一次，上午完成不能跳过下午；失败或需要用户动作时报告具体原因；未发生变化时静默。应用关闭时不执行本地采集，错过的内容合并到下一次可运行的09:00或14:00批次处理，不另外创建高频补跑检查，不能承诺打开应用瞬间触发。只记录实际返回的调度状态。

## 双工具检索（每轮必做）

每轮收集至少使用两种不同的实际检索工具，默认组合为 Scrapling + Firecrawl：Scrapling 直接检查官方或行业网站、公告、归档及候选原文；Firecrawl 执行关键词搜索和补漏，并按需要读取新发现的页面。分别保存具体入口/关键词、实际取得的内容和失败情况，合并线索后去重，再逐条核验。不能只调用一个工具就标记本轮收集完成。

工具按 collection-config.json 中的规范 ID 记录：scrapling、firecrawl、web-search、browser。Scrapling 普通抓取与浏览器模式只算一种工具；Firecrawl search 与 scrape 也只算一种。默认工具不可用时使用另一种实际可用的检索工具补足两种；工具调用失败、只完成环境检查或只读取本地缓存不算成功检索。仍不足两种时 run.status=partial，说明缺口，不伪报完成。

双工具用于扩大检索覆盖，不等于两个独立事实来源。两个工具读同一篇新闻仍只有同一来源；真实性核验继续按共享 sourcing 规则判断。

## 本地入口

项目根目录由当前技能位置向上三级定位，命令在根目录执行，Python 3.10+。Python 不在 PATH 时调用 Codex 提供的 workspace dependencies 找到当前电脑运行时。不要复制其他电脑的用户名、盘符、虚拟环境或端口。默认 shell 无法启动时，可用现有 Node 工具的 child_process.execFile 直接调用找到的 Python，以参数数组传入命令，不把工具启动失败当作新闻来源不可用。

- 首次自检：python scripts/daily_news.py check
- 判断当前批次是否需要运行：python scripts/daily_news.py due；可用 --slot 09:00 或 --slot 14:00 明确本轮时段。返回 slot 随本次采集保留到 run.slot
- 抓取可选环境：读取项目 ../scrapling/SKILL.md，运行 python scripts/news_tools.py check；缺少环境时依其 setup 流程安装，或使用已可用网页读取工具继续。
- 新闻发现、原文阅读、交叉核验由 Codex 调用当前可用工具执行。daily_news.py 负责数据校验与发布，并不执行网络检索，也不替代事实核验。
- 发布本次核验结果：python scripts/daily_news.py publish .news-output/daily-YYYY-MM-DD.json
- 重新生成已有报告：python scripts/daily_news.py render outputs/news/YYYY-MM-DD.json

## 每次运行

1. 读取当天北京时间与 due 结果。每天09:00和14:00各运行一轮，仅返回的本批次已经完成时静默结束，不浏览网页、不改写核验时间、不重复推送。下午必须在上午结果基础上增量收集，不能因当天已有 completed 日报而跳过。用户明确要求手动收集时允许即时刷新。保留当天已有 ID 和已核验事实，新增事件接续编号。同一事件同一阶段合并来源，新的实质性进展单独记录并关联旧 ID。
2. 若需收集，先读最近成功报告与其原始采集时间。首次查近15个自然日；以后从上次成功时间前24小时开始补漏；错过日期时扩大到遗漏时段，最长回看15天。不得伪造错过日期的历史日报，补到的内容按实际收录日入档。
3. 先完成上述双工具检索，记录 retrievalTools。按 collection-config.json 的范围与入口，完成 P0 直接访问或实际失败记录，并逐个覆盖工程项目、营地住宿、产品材料、采购招投标、合规政策、航运物流。结合英文及必要阿拉伯语检索，按新发现的项目业主、承包商、港口、船公司追到原文。优先级与替代方式依共享 sourcing 规则。不因已有三条就停止，不以全部新闻都必须关联产品缩窄行业收集。
4. 每条候选在本次收集内完成核验：原文、发布/事件日期、主体、地点、阶段、数字和范围。追到可证明该命题的一手公告，或独立可靠来源交叉核对。同一原稿的转载、翻译或同一通讯稿不算独立第二来源。企业自述只核验它确实发布了相应内容；项目总规划不改写为施工授标或营地采购。访问失败按共享规则切换；穷尽本轮合理可用来源后给出明确结果，不留笼统“待系统核验”。
5. 按 references/report-format.md 写入临时 JSON，所有条目都有最终核验结果、真实核验时间、方法、结论和来源。通过则 verified；仍缺关键证据则 unconfirmed，并逐条写清实际查了什么、缺什么、为何没通过。未通过记录完整保留，默认列表只展示 verified。核验过部分基本事实时按该范围写摘要，不能把型号清单等未确认部分变成事实。
6. 需要产品关联时读 knowledge/AI资料导航索引.md 与最小相关原始资料；只填打包箱、移动卫浴、五金、薄壁轻钢中真实适配项和各自理由。产品资格与新闻真假分别判断，不把产品不适配标成新闻未核验。航运保留船公司、货类、港口、航向、生效条件及费用口径。公司能力或公司参与新闻项目均须另有证据。
7. 保存实际访问日志与必要原文摘录到 outputs/news/evidence-YYYY-MM-DD/，写明 URL、工具、抓取时间、实际读到内容与失败原因。每条通过记录的关键事实应能回到这些证据或本次读到的原文；不要保存账号凭证。旧数据沿用时保留旧 checkedAt，只有实际重查才更新时间。
8. 运行 publish；校验失败先修复缺项，不把 verified 改成宽泛措辞绕过缺失证据。成功后检查 HTML 的记录总数、状态数量、抽样核验弹层和选题复制。HTML 内包含全部本轮条目及核验信息；最近15天可切换，日期、渠道、编号与复制指令均来自所选日报。
9. 成功完成本轮收集后 run.status=completed，并把 due 返回的时段写入 run.slot（09:00或14:00）；publish 自动合并当天 completedSlots，分别防止两轮重复执行。其中可以有已经查证但证据不足的 unconfirmed 新闻。采集本身中断、关键范围没检查或全部工具不可用时标 partial/failed 并记录未完成项，供下一次计划批次或用户手动重试；不创建额外高频轮询。不能将网络不可用伪装成“零条新闻”。无新增但已完成检索可交付零新增报告。
10. 每个计划批次完成后在新闻对话推送一次简短中文汇报：本轮时段、实际收录总数、已核验/未通过数量、新增或更新数量、HTML 绝对路径链接；有重要访问限制时说明。上午和下午即使没有新增，也各汇报一次本轮实际检索结果。同一批次重复触发且已完成时保持静默。计划时点启动收集与核验，完成后发送汇报，不承诺恰好整点完成网络核验。

## 完成标准

首轮入口可运行，自动化工具返回 ACTIVE 且目标项目/对话正确；模板与脚本通过自检；每轮至少两种工具有实际检索记录，发布校验通过；HTML 的每条新闻都包含本次实际完成的核验结果；上午完成后上午批次 due=false、下午批次 due=true；下午完成后两个批次均 due=false，跨北京时间日期重新开始。自动化关闭、电脑休眠、无网络或无可用账号额度时如实报告可用性，不声称已在后台收集。
